# 家庭庫存管理 V19：Excel 匯入／匯出修正版

## 本版內容
- 庫存查詢新增「下載庫存 Excel」與「選擇 Excel 上傳」。
- 匯出目前篩選條件下的有庫存批次；每列帶入資料庫既有 UUID 批次識別碼，使用者不需輸入或修改。
- Excel 有批次識別碼：比對既有批次。商品名稱與有效期限必須與原批次相符；其餘批次欄位以 Excel 內容覆蓋更新；預覽會列出實際差異欄位，並以數值比較避免小數格式差異造成誤判。
- Excel 空白批次識別碼：新增批次，商品必須已存在於物品管理主檔；若物品識別碼留白，僅在物品名稱唯一相符時自動對應，同名商品仍須填入物品識別碼；系統自動產生新批次 ID。
- 同一份檔案中同一 ID 出現多次：只處理第一次出現的資料列，後續列忽略且不寫入忽略原因或異動紀錄。
- 同一份完全相同的 Excel 重複上傳：透過檔案 SHA-256 指紋及來源列號，避免空白 ID 的新批次被重複建立。
- 數量變動會寫入 stock_transactions adjustment；每筆成功新增／修改另寫入 inventory_import_logs，保留前後資料。
- 分類、購買通路、單位成本、計量單位可更新物品主檔。同一物品多個匯入列若這些主檔欄位內容互相衝突，本次先略過該物品的主檔欄位更新，但批次層級更新仍可進行。
- 不會因為 Excel 刪除某列而刪除資料庫批次；不允許透過 Excel 改商品名稱或改有效期限識別條件。

## 更新前必要步驟
1. 先備份 Supabase 現有資料（至少匯出 items、inventory_batches、stock_transactions）。
2. 在 Supabase SQL Editor 執行 `excel_import_migration.sql` 一次，建立匯入稽核表與 RLS。
3. 將 `index.html`、`styles.css`、`app.js` 上傳並覆蓋 GitHub Repository 同名檔案。
4. 保留 app.js 原本的 Supabase URL 與 publishable/anon 公開金鑰。
5. 等 GitHub Pages 部署完成，Ctrl+F5 重新整理。

## V19 修正內容
- 修正新增批次時物品識別碼留白的處理：唯一同名商品可自動配對，不會因為只留白批次識別碼而誤判失敗。
- 若存在多筆同名物品，仍要求填入物品識別碼，避免庫存掛錯商品。
- 匯入預覽的更新原因改為顯示差異欄位，數量與金額採數值比較，降低 Excel 儲存格格式差異造成的假更新。

## 建議測試順序
1. 先下載 Excel，不要先改內容。
2. 再上傳同一份 Excel，應該沒有批次被新增；內容相同的列會顯示無變更／忽略。
3. 修改一筆既有批次的剩餘數量與位置後上傳，確認數量覆蓋更新，異動紀錄有 adjustment。
4. 新增一列、批次識別碼留白，對應既有物品主檔後上傳，確認新增批次與 receive 紀錄。
5. 再上傳同一個含空白 ID 的原檔，確認不會重複建立。

## 本版暫不處理的高風險情況
- 透過 Excel 建立全新的物品主檔、分類或存放位置。
- 透過 Excel 刪除批次或物品。
- 變更既有批次的商品名稱或有效期限。
- 同一物品多批次的主檔欄位互相衝突時，自動猜測哪一筆為準。

## 重要限制
本版為可供實際小量測試的第一版。匯入以逐列方式寫入，若網路中斷或某列遇到資料庫錯誤，可能出現部分成功；請依匯入結果及異動紀錄檢查後再重試。不要直接拿唯一正式庫存檔第一次測試，請先用少量資料驗證。


## V19 修正
- 修正批次未設定獨立存放位置、但畫面沿用物品預設位置時，Excel 匯出再匯入被誤判為「存放位置更新」的問題。
- 比對時改以批次實際位置或物品預設位置作為有效位置。
- 若批次原本沿用物品預設位置，其他欄位更新時仍保留批次位置為空值，不會不必要地寫入重複位置。
